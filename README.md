# MaxToTelegram

Telegram-бот, который зеркалит сообщения из группы в мессенджере **Max** в группу в **Telegram**: текст, фото, видео, документы и стикеры.

Бот не нужно добавлять в исходную группу. Он читает историю чата через внешний API (сейчас Green API) и пересылает всё новое.

## Как это работает

```
Max-группа ──► Green API (getChatHistory) ──► MaxBridge ──► Telegram-группа
                                                  │
                                                  └─► (приоритетный отправитель) личка ──► пересылка в группу
```

1. Раз в `CHECK_TIME` секунд (по умолчанию 10) бот запрашивает историю чата у API.
2. Из ответа отбираются сообщения поддерживаемых типов, которых ещё нет в `history.json`, и сортируются по времени.
3. Для каждого нового сообщения:
   - определяется имя отправителя (по `ids.json`, иначе берётся имя из API);
   - текст переводится из «мессенджерной» разметки в Telegram HTML;
   - медиа скачивается во временную папку, при необходимости конвертируется и отправляется;
   - после успешной отправки файл удаляется с диска.
4. Обработанные сообщения записываются в `history.json`, чтобы не отправлять их повторно.

### Типы сообщений

| Тип в API | Что делает бот |
|---|---|
| `textMessage`, `extendedTextMessage` | отправляет текст |
| `imageMessage` | скачивает, конвертирует в PNG, отправляет как фото |
| `videoMessage` | скачивает, отправляет как видео (со стримингом) |
| `documentMessage` | скачивает, отправляет документом с исходным именем |
| `stickerMessage` | скачивает, конвертирует в WEBP, отправляет как стикер |

Если подпись длиннее 1024 символов (лимит Telegram), медиа уходит без подписи, а текст отдельным сообщением.

### Форматирование текста

- `[текст](ссылка)` → кликабельная ссылка
- голые `http(s)://...` → кликабельная ссылка
- `*жирный*` → **жирный**
- `_курсив_` → *курсив*
- остальное экранируется, так что случайные `<` и `&` ничего не ломают

### Приоритетный отправитель

Сообщения от пользователя с ID `PRIORITY_ID` обрабатываются иначе:

- уходят без подписи «Сообщение от …»;
- сначала отправляются в личку `PERSONAL_ID`, а оттуда **пересылаются** (forward) в группу.

Остальные сообщения отправляются прямо в группу с подписью `📘 Сообщение от <имя>:`.

### Команда `/start`

Показывает аптайм бота (с момента запуска процесса).

## Установка

Нужны Python 3.10+ и бот, созданный через [@BotFather](https://t.me/BotFather), которого нужно добавить в целевую Telegram-группу.

```bash
git clone https://github.com/<your-name>/maxbridge.git
cd maxbridge
python -m venv venv
source venv/bin/activate
pip install "aiogram>=3" aiohttp aiofiles pillow
```

## Настройка

Все параметры лежат константами в `.env`.

| Параметр | Что это |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота от BotFather |
| `GROUP_ID` | ID Telegram-группы, куда пересылаем (для супергрупп начинается с `-100`) |
| `PERSONAL_ID` | ID чата, куда сначала уходят сообщения приоритетного отправителя |
| `PRIORITY_ID` | ID отправителя в исходном чате, чьи сообщения идут без подписи |
| `API_URL` | полный URL метода `getChatHistory` с вашим instance и токеном |
| `chatId` (в `check_new_messages`) | ID исходного чата, из которого читаем историю |
| `CHECK_TIME` | интервал опроса в секундах |

### Имена отправителей (необязательно)

Файл `ids.json` сопоставляет ID отправителя с отображаемым именем:

```json
[
  { "id": "43998517", "name": "Иван Иванов" },
  { "id": "12345678", "name": "Мария Петрова" }
]
```

Если ID в файле нет, используется имя из ответа API.

## Запуск

```bash
python bot.py
```

При первом запуске создаются папки `images/`, `videos/`, `documents/`, `stickers/` и файл `history.json`.

### Автозапуск через systemd

```ini
# /etc/systemd/system/maxbridge.service
[Unit]
Description=MaxBridge
After=network-online.target

[Service]
WorkingDirectory=/opt/maxbridge
ExecStart=/opt/maxbridge/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now maxbridge
journalctl -u maxbridge -f
```

## Как заменить источник данных

Весь код, который общается с внешним API, находится в `check_new_messages`. Остальные функции работают с обычными словами-полями сообщения: `idMessage`, `senderId`, `senderName`, `textMessage`, `caption`, `typeMessage`, `downloadUrl`, `fileName`, `timestamp`. Если нужно перейти на собственный парсер, достаточно, чтобы он возвращал список словарей в таком формате.

## Известные ограничения

- Сообщения длиннее 4096 символов Telegram не примет, они не будут отправлены.
- Если отправка или скачивание файла упали, сообщение всё равно попадает в `history.json` и повторно не отправляется.
- Анимированные GIF при конвертации в PNG теряют анимацию.
- История читается и перезаписывается целиком при каждом цикле, поэтому `history.json` со временем разрастается.
- Нет обработки лимитов Telegram (`429 Too Many Requests`): при большом потоке сообщений часть может потеряться.
